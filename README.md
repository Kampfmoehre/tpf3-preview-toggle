# Vehicle 3D Preview Toggle (Transport Fever 3)

A small UI mod for Transport Fever 3 that adds a **"3D preview" checkbox to
vehicle windows**. Unchecking it removes the live 3D camera preview from all
vehicle windows; the camera button and the speed display stay in place.

Why: an open vehicle preview can cost a lot of performance. On my machine (Linux/Vulkan) it
roughly halved the frame rate as long as the window is open (GPU load drops
from ~99 % to ~70 %, see the
[forum report](https://forum.urbangames.com/forum/index.php?thread/3958-verringerte-performance-mit-fahrzeugfenster/)).
With the preview switched off the frame rate goes back to normal.

- The checkbox state is shared by all vehicle windows and lasts for the
  session.
- The initial state ("3D preview at game start", Off/On) can be chosen per
  savegame in the mod settings when loading a game.
- Purely cosmetic: achievements stay enabled.
- English and German.

Available on mod.io: <https://mod.io/g/transportfever3/m/vehicle-3d-preview-toggle1>

## Installation

Subscribe on mod.io or in the in-game Mod-Hub, then enable the mod when
loading or creating a game.

Manual installation: copy the folder `kampfmoehre_preview_toggle_1` into the
game's local mod directory, on Linux
`~/.local/share/Steam/userdata/<steam-id>/3493540/local/mods/`.

## How it works

Transport Fever 3's UI is written in Lua/Teal on top of an in-house,
React-like component system. Mods can hook into it through
`react-plugin` resources:

- `entry.res.lua` registers a plugin at the game's `ModEntryPointExtension`,
  which loads `preview_toggle.script.lua` into the GUI Lua state as soon as
  the game UI is built.
- The script wraps `builtin.EntityRendererComponent` (the live preview). For
  vehicles it returns an empty placeholder while the preview is off, so no
  preview camera is created at all. It also re-keys the enclosing
  `FloatingLayout` so the overlay widgets get fresh geometry when toggling.
- `toggle.res.lua` registers the checkbox as a plugin at the
  `VehicleEowExtensionPoint`, i.e. it is rendered like the game's own
  vehicle window widgets.
- The mod parameter is declared in `mod.json` and read with
  `api.engine.config.getModParams()` (values are 1-based).
- `strings.json` holds the translations.

## Development

```
kampfmoehre_preview_toggle_1/      the mod (this is what gets published)
  mod.json                         mod id, parameters
  strings.json                     translations (en, de)
  _metadata/modinfo.json           name, summary, description (+ de)
  _metadata/0.png                  title image, 1920x1080
  content/gui/kampfmoehre_preview_toggle/
    entry.res.lua                  plugin registration (entry point)
    toggle.res.lua                 plugin registration (vehicle window)
    preview_toggle.script.lua      the actual code
sync.sh                            copies the mod into the game's staging area
```

Workflow (Linux):

1. Edit the files in `kampfmoehre_preview_toggle_1/`.
2. Run `./sync.sh`. It copies the mod into the game's staging area
   (`.../userdata/<steam-id>/3493540/local/staging_area/`), where the game
   loads it as a development mod. Returning to the main menu and reloading
   the savegame is enough to pick up changes, no restart needed.
3. Lua errors show up as a red error screen in the game ("Copy to clipboard")
   and in `.../3493540/local/crash_dump/stdout.txt`. The script logs with the
   prefix `[preview_toggle]`.
4. Before uploading a new version through the in-game Mod-Hub, increase
   `revision` in `mod.json`. mod.io rejects a package whose content is
   byte-identical to an already uploaded one.

The staging copy also contains files generated by the game (`.cooked_*`,
`_metadata/mod.io_fileid.txt`). `sync.sh` leaves them alone and they are
ignored by git.
